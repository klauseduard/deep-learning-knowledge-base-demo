SGD by the Numbers

A worked example of stochastic gradient descent: mini-batches, gradient averaging, and parameter updates — with real arithmetic at every step.

The gradient descent interactive shows what SGD looks like from the outside — trajectories on a loss landscape. The backpropagation walkthrough shows how to compute gradients for a single example. This page fills the gap between them: how SGD uses those per-example gradients to actually update parameters.

1. The Setup

We use the same tiny network as the backpropagation walkthrough:

$x \xrightarrow{w_1} z_1 = w_1 x + b_1 \xrightarrow{\sigma} a_1 = \sigma(z_1) \xrightarrow{w_2} \hat{y} = w_2 a_1 + b_2 \xrightarrow{\mathcal{L}} L = \tfrac{1}{2}(\hat{y} - y)^2$

In practice, "SGD" almost always means mini-batch SGD. We'll use batch size $B = 3$, giving us 2 mini-batches per epoch.

2. One SGD Step, in Detail

Suppose the first mini-batch contains examples 1, 2, and 3. The SGD recipe is:

  1. Run the forward + backward pass on each example in the batch (3 backward passes)
  2. Average the per-example gradients
  3. Update each parameter: $w \leftarrow w - \eta \cdot \overline{\nabla L}$
Step 1 / 9
Each example "pulls" the parameters in a slightly different direction. Averaging smooths out these conflicting signals. A larger batch gives a smoother average (closer to the true gradient) but costs more compute per step.

3. Why "Stochastic"?

The word stochastic means "random." Each mini-batch is a random sample from the dataset, so the gradient computed from it is a noisy estimate of the true (full-batch) gradient. Different random draws give different gradients:

Batch randomness: same parameters, different batches

Each row shows the averaged gradient for $w_1$ from a different random batch of 3 examples. The true (full-batch) gradient uses all 6 examples.

Each mini-batch gradient is a noisy estimate of the true gradient. Over many steps, the noise averages out and SGD converges — but the noise along the way is beneficial. It prevents the optimizer from settling into sharp minima that memorize training data, acting as implicit regularization. This is why SGD often generalizes better than full-batch gradient descent.

4. Multiple Epochs

One epoch = one complete pass through the dataset. With 6 examples and batch size 3, one epoch is 2 SGD steps. Watch the parameters and loss evolve over several epochs.

What we skipped: Real SGD training involves learning rate schedules (warmup + cosine decay), momentum, weight decay, and adaptive optimizers like Adam. These build on the same core loop shown here — compute gradients, average over a batch, update parameters — but modify how the gradient is used.
