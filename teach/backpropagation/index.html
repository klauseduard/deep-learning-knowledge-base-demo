1. Partial Derivatives Refresher

A derivative tells you the rate of change. If $f(x) = x^2$, then $\frac{df}{dx} = 2x$ means: "at any point $x$, if you nudge $x$ by a tiny amount $\epsilon$, $f$ changes by approximately $2x \cdot \epsilon$."

A partial derivative is the same idea when a function has multiple inputs. If $f(x, y) = x^2 y + 3y$, then:

  • $\frac{\partial f}{\partial x}$ = "how does $f$ change when I wiggle $x$, holding $y$ fixed?"
  • $\frac{\partial f}{\partial y}$ = "how does $f$ change when I wiggle $y$, holding $x$ fixed?"

To compute $\frac{\partial f}{\partial x}$, treat $y$ as a constant and differentiate normally with respect to $x$:

$f(x, y) = x^2 y + 3y \quad \Rightarrow \quad \frac{\partial f}{\partial x} = 2xy \quad$ (the $3y$ term vanishes — it doesn't depend on $x$)
$\frac{\partial f}{\partial y} = x^2 + 3 \quad$ (the $x^2$ is treated as a constant multiplier of $y$)

The collection of all partial derivatives is called the gradient:

$\nabla f = \left(\frac{\partial f}{\partial x}, \frac{\partial f}{\partial y}\right)$

In neural networks, the gradient of the loss with respect to all parameters is exactly what we need to do gradient descent. The question is: how do we compute this efficiently when there are millions of parameters?

2. The Chain Rule — Derivatives of Composed Functions

Neural networks are compositions of functions — the output of one layer feeds into the next. To differentiate a composition, we need the chain rule.

Single-variable chain rule

If $y = f(g(x))$ — i.e., first apply $g$, then apply $f$ to the result — then:

$\frac{dy}{dx} = \frac{df}{dg} \cdot \frac{dg}{dx}$

In words: the derivative of the whole thing = (derivative of the outer function) $\times$ (derivative of the inner function). Each evaluated at the appropriate point.

Concrete example: $y = (3x + 1)^2$

Let $g(x) = 3x + 1$ (inner) and $f(u) = u^2$ (outer), so $y = f(g(x))$.

$\frac{dg}{dx} = 3$ ← derivative of inner function
$\frac{df}{du} = 2u$ ← derivative of outer function
$\frac{dy}{dx} = \frac{df}{du}\bigg|_{u=g(x)} \cdot \frac{dg}{dx} = 2(3x+1) \cdot 3 = 6(3x+1)$ ← chain rule

Multi-variable chain rule

This generalizes naturally. If $z$ depends on $x$ through multiple intermediate variables, we sum over all paths. For $z = f(a, b)$ where $a = g(x)$ and $b = h(x)$:

$\frac{dz}{dx} = \frac{\partial f}{\partial a} \cdot \frac{da}{dx} + \frac{\partial f}{\partial b} \cdot \frac{db}{dx}$

This is the foundation of backpropagation: each node in the network receives gradient contributions from all the paths through which it affects the loss.

The chain rule says: to find how the output depends on an input, multiply the local derivatives along each path from input to output, and add up all paths. Backpropagation is just an efficient way to do this multiplication and summation.

4. How Automatic Differentiation Actually Works

Here's the question you asked: is there real differentiation happening, or is it some kind of approximation?

Yes, there is real differentiation — but not the kind you did in calculus class. Autograd doesn't manipulate symbolic expressions and it doesn't use numerical approximations. It applies exact analytical derivative rules to each primitive operation, evaluated at the concrete numerical values from the forward pass.

The three kinds of differentiation

There are exactly three ways a computer can compute derivatives:

Method How it works Exact? Cost
Numerical
(finite differences)		 Evaluate $\frac{f(x+\epsilon) - f(x)}{\epsilon}$ for small $\epsilon$ No — approximation with rounding errors $O(n)$ forward passes for $n$ parameters
Symbolic
(CAS, like Mathematica)		 Manipulate the expression algebraically: $\frac{d}{dx}[x^2] \rightarrow 2x$ Yes — exact symbolic expression Expression can explode in size ("expression swell")
Automatic
(autograd)		 Apply derivative rules to each op, propagate numbers (not expressions) Yes — exact to floating-point precision One backward pass, regardless of parameter count

What autograd does, step by step

During the forward pass, the framework records a computational graph — a DAG where each node is a primitive operation (add, multiply, exp, etc.) and each edge is a tensor value. Crucially, each node also knows its own local derivative rule.

During the backward pass, autograd walks this graph in reverse. At each node, it:

  1. Receives the gradient of the loss w.r.t. its output (a number, not a symbol)
  2. Multiplies by its local derivative (evaluated at the concrete values from the forward pass)
  3. Passes the result to its input nodes

This is the vector-Jacobian product (VJP): given an upstream gradient vector $\bar{v}$, compute $\bar{v} \cdot J$ where $J$ is the Jacobian of the local operation.

So: every single derivative in backpropagation is a real, analytically correct derivative of a primitive function (multiply, add, sigmoid, square, ...), evaluated at a concrete number. There is no approximation. There is no symbolic manipulation of expressions. The chain rule is applied mechanically by multiplying these numerical local derivatives together in reverse order.

Why "automatic"?

The word "automatic" doesn't mean "approximate" or "magical." It means: the programmer only writes the forward computation, and the framework automatically constructs and executes the backward computation. Before autograd, researchers had to manually derive and implement the backward pass for every new architecture — tedious and error-prone. Autograd does this correctly and automatically by composing the known derivatives of primitive operations.

A subtle point: autograd computes derivatives that are exact in exact arithmetic. In practice, floating-point rounding introduces tiny errors — but these are the same rounding errors you'd get computing the derivative by hand and evaluating it. They're not an inherent limitation of the method, unlike finite differences where the approximation error is fundamental.

5. Three Ways to Compute Derivatives — Side by Side

To make the comparison concrete, let's compute $\frac{\partial L}{\partial w_1}$ for our example network using all three methods.

Method 1: Numerical (finite differences)
Pick $\epsilon = 0.0001$
Forward pass with $w_1 = 0.5$: $L = 0.16498$ (computed earlier)
Forward pass with $w_1 = 0.5001$: $L = 0.16491$
$\frac{\partial L}{\partial w_1} \approx \frac{0.16491 - 0.16498}{0.0001} = \mathbf{-0.0710}$

Requires one extra forward pass per parameter. For a model with 1 billion parameters, that's 1 billion forward passes. Also introduces approximation error from the choice of $\epsilon$.

Method 2: Symbolic (pen and paper / CAS)
$L = \frac{1}{2}\left(w_2 \cdot \sigma(w_1 x + b_1) + b_2 - y\right)^2$
$\frac{\partial L}{\partial w_1} = (w_2 \sigma(w_1 x + b_1) + b_2 - y) \cdot w_2 \cdot \sigma(w_1 x + b_1)(1 - \sigma(w_1 x + b_1)) \cdot x$
$= (-0.5740) \cdot (-0.3) \cdot (0.6682)(0.3318) \cdot 1.5 = \mathbf{-0.0573}$

Exact, but the expression grows combinatorially with network depth. For a 100-layer network, the symbolic expression would be unmanageably large. Also recomputes shared subexpressions — $\sigma(w_1 x + b_1)$ appears three times above.

Method 3: Automatic differentiation (what PyTorch does)
Forward pass stores: $z_1 = 0.85$, $a_1 = 0.7003$, $\hat{y} = 0.1899$, $L = 0.1862$
Backward — each step is one multiplication of numbers:
$\frac{\partial L}{\partial \hat{y}} = -0.6101$
$\frac{\partial L}{\partial a_1} = -0.6101 \times (-0.3) = 0.1830$
$\frac{\partial L}{\partial z_1} = 0.1830 \times 0.2099 = 0.0384$
$\frac{\partial L}{\partial w_1} = 0.0384 \times 1.5 = \mathbf{0.0576}$

Exact (same as symbolic, up to float rounding), but works only with numbers — no expression manipulation. Cost: one backward pass computes gradients for all parameters simultaneously.

The numerical method gives a slightly different answer (-0.0710 vs. -0.0573/0.0576) because finite differences are inherently approximate. The symbolic and autodiff methods agree to floating-point precision — they're computing the same mathematical quantity, just via different computational strategies. (The small discrepancy between the symbolic and autodiff values here is purely float rounding in intermediate steps.)

Why reverse mode?

Automatic differentiation comes in two "modes":

  • Forward mode: propagate derivatives alongside the forward computation. For each input variable, one forward pass gives the derivative of all outputs w.r.t. that one input. Cost: one pass per input variable.
  • Reverse mode: propagate derivatives backward from the output. One backward pass gives the derivative of one output w.r.t. all input variables. Cost: one pass per output variable.

Neural network training has one output (the scalar loss) and millions of input variables (the parameters). Reverse mode needs one backward pass. Forward mode would need one pass per parameter. This is why backpropagation — which is reverse-mode autodiff — is the efficient choice.

Forward mode: 1 output, $n$ parameters → $n$ passes 😰
Reverse mode: 1 output, $n$ parameters → 1 pass 🎉

For GPT-4 with ~1.8 trillion parameters, that's 1 pass vs. 1,800,000,000,000 passes.
