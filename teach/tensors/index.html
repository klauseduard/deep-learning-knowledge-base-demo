Memory Layout & Strides

A tensor is stored as a flat array in memory. The stride for each dimension tells you how many elements to skip to move one step along that axis.

For a row-major tensor of shape $(D_1, D_2)$, the strides are $(D_2, 1)$ — moving along the last dimension steps through contiguous memory.

shape: (3, 4)
strides: (4, 1)
elements: 12
order: row-major
Row-major means the last dimension is contiguous in memory — adjacent elements in the last axis sit next to each other in RAM.

Reshape / Transpose / Slice

Reshape changes the shape metadata without moving data — the flat memory stays the same, only the interpretation changes.

Transpose swaps dimensions by swapping strides — the data doesn't move, but the access pattern changes.

Slice selects a sub-region by adjusting the offset and shape.

before: shape (3,4), strides (4,1)
after: —
data copied: no
Reshape and slice don't copy data — they only change metadata. Transpose swaps strides, making the tensor non-contiguous.

Broadcasting

Broadcasting lets you perform operations on tensors of different shapes. Dimensions of size 1 are virtually expanded to match the other tensor — no data is actually copied.

Rules: align shapes from the right; dimensions must be equal or one of them must be 1.

Step 0 / 3
A shape: (3, 1)
B shape: (1, 4)
result: (3, 4)
The expansion is virtual — no data is copied. Broadcasting is just a clever indexing trick: dimension-1 axes reuse the same single value for every position.
